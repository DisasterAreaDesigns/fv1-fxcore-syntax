# fv1-fxcore-syntax

Syntax highlighting for the two DSP assembly languages used in this shop:

| Language | Extensions | Grammar |
|---|---|---|
| SpinASM (Spin FV-1) | `.spn` | `syntaxes/spinasm.tmLanguage.json` |
| FXCore | `.fxc` `.fxo` `.fxl` | `syntaxes/fxcore.tmLanguage.json` |

Packaged as a VS Code / Theia plugin, so it works in the Arduino IDE dev fork
as well as in VS Code.

## The grammars are generated, not hand-written

Do not edit anything in `syntaxes/`. Both files are emitted by the scripts in
`tools/`, from a single source of truth per language:

    python3 tools/gen-spinasm.py     # reads asfv1.py's own tables
    python3 tools/gen-fxcore.py      # ISA list embedded, asserted complete

**SpinASM** is generated by reading the mnemonic, register and LFO tables
straight out of `asfv1.py` in the `asfv1-extended` repo. asfv1 is the
assembler these programs are actually built with, so it is the authority --
ahead of Spin's published instruction-syntax page, which is reference material
and is not exhaustive. (It omits `LDAX`, for one, which is a real assemblable
pseudo-op.) Regenerating after an asfv1 change picks up new mnemonics for free.

**FXCore** has no machine-readable source to scrape, so the 72 instructions of
the September 2025 instruction set are listed in the generator, split into
categories, with an assertion that the categories union to exactly that set.
Adding an instruction to the ISA list without categorising it fails the script
rather than silently producing an unhighlighted mnemonic.

## Checking the grammars against real code

    python3 tools/check-coverage.py [corpus-root ...]

Scans every `.spn`/`.fxc` under the given roots (default: `~/Documents/GitHub`
and Dropbox) and reports every run of source no rule in the grammar matches.
It is a left-to-right scanner, not a word splitter, so `0x7f8000` is consumed
whole rather than mis-reported as an identifier. Symbols a file declares for
itself are subtracted, case-insensitively.

Current state, over 839 `.fxc` and 1151 `.spn` files:

* FXCore -- full coverage.
* SpinASM -- 3 unmatched tokens, all in files `asfv1` itself refuses to
  assemble. `cos0`/`cos1` in particular are not FV-1 tokens; asfv1 rejects
  them as undefined labels, so leaving them uncoloured is correct.

Anything new that shows up here is either a hardware name the grammar is
missing or an ISA addition that needs categorising.

## Scope assertions

    npm install --no-save vscode-textmate vscode-oniguruma
    node tools/test-scopes.mjs

Tokenises sample lines through the real Oniguruma engine -- the same one the
IDE uses, not Python's `re` -- and asserts the scope of specific tokens. This
is what catches Oniguruma/PCRE differences that the generators cannot.

## Testing in the IDE without a rebuild

The installed Theia backend honours `THEIA_PLUGINS`, so there is no need to
rebuild the IDE to try a change. Point it at a directory whose *children* are
plugins -- not at `~/Documents/GitHub`, which would try to load every repo
there as a plugin:

    mkdir -p ~/.theia-dev-plugins
    ln -sfn ~/Documents/GitHub/fv1-fxcore-syntax ~/.theia-dev-plugins/

    THEIA_PLUGINS=local-dir:$HOME/.theia-dev-plugins \
      "/Applications/Arduino IDE dev.app/Contents/MacOS/Arduino IDE dev"

Quit any running instance first, or the new environment is not picked up.

## Notes

A sizeable minority of shipped `.spn` files are UTF-16LE with no BOM. Editors
that assume UTF-8 render them as one character per line; that is a file
encoding issue, not a highlighting one.
